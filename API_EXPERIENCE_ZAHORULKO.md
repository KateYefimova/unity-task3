# Мій досвід користування framework / API (Загорулько)

Роль: AI-assisted Framework Developer. Архітектор framework — Єфімова.

## 1. Налаштування: як я підключала свої стани до framework

### Нова поведінка ворога через extension API (`IEnemyBehaviour`)
1. Створити компонент, що реалізує `IEnemyBehaviour` (`Initialize`, `Enter`, `Execute`, `Exit`, `Restart`, `IsBusy`).
   У мене це `ChargeBehaviour`: windup (миготіння червоним) → ривок до гравця → повернення → cooldown → знову готовий.
2. Повісити його на ворога разом з `ChargerEnemy` (наслідує `BaseEnemy`). `ChargerEnemy` бере поведінку через
   `GetComponent<IEnemyBehaviour>()`, тобто не знає, що це саме Charge — поведінку можна замінити іншою.
3. Перевірка в рівні: підійти до `ChargerEnemy` у `VerticalSlice_Level` / `level2` і дивитися Console:
   `[EnemyBehaviour] ENTER` → `EXECUTE` → `EXIT` → `RESTART`, після чого ворог знову може атакувати.

### Interaction-сценарій гравця (Animation Event)
- Клавіша **E** → `PlayerInteraction` → `PlayerAnimationRelay.TriggerAction()` → стан `Player_Action`.
- На кліпі `Player_Action.anim` дві події:
  `OnInteractionImpact` (0.25 с, момент дії, **один** `Debug.Log`) і `OnInteractionFinished` (кінець кліпу).
- Перехід `Player_Action → Idle` тепер по Exit Time = 1 (кліп програється повністю), повторний тригер під час дії ігнорується.

### Hurt / Death ворога
- `EnemyReactions` на префабі `Enemy_ProximityMine`. Тестові клавіші: **J** — Hurt, **L** — Death
  (спрацьовують лише для ворогів у радіусі 8 від гравця).
- Death: логіка й колайдер ворога вимикаються (`BaseEnemy.SetLogicActive(false)`), грає `Anim_Mine_Death`,
  подія `OnDeathAnimationFinished` ховає спрайт, через 1.5 с ворог відроджується (можна тестувати повторно).
- Hurt: кліп більше не зациклений, подія `OnHurtAnimationFinished`, повернення в Idle після кінця кліпу.

## 2. Незручності framework, які я помітила

| Що | Чому це заважало | Що зроблено в моєму PR |
|---|---|---|
| Файл `ChargeEnemy.cs` містив клас `ChargerEnemy` | Unity вимагає однакову назву файлу й класу — скрипт на префабі не підключався | Перейменовано на `ChargerEnemy.cs` (GUID збережено) |
| `IEnemyBehaviour` не мав `Initialize` / `IsBusy` | Ворог мусив знати конкретний клас `ChargeBehaviour`, тобто «extension point» не працював як розширення | Додано в інтерфейс |
| Animation Event отримують **усі** компоненти на об'єкті з Animator | `OnInteractionEvent` був і в `PlayerAnimationRelay`, і в `AnimationFeedbackHandler` → ризик дубльованих логів | Окремі імена подій, обробник один (`PlayerInteraction`) |
| Тригер `Action` гравця ніхто не викликав | `AnimationFeedbackHandler` з клавішею E висів на міні, в Animator міни параметра `Action` немає | Тестовий тригер перенесено на гравця, `AnimationFeedbackHandler` видалено |
| Death ворога = scale → 0 без виходу | Невидима міна продовжувала «вбивати» гравця, повторно протестувати не можна | `EnemyReactions` + `SetLogicActive` + revive |
| `PlayerHealth` робив усе (HP, knockback, падіння, respawn) | Важко зрозуміти, де що змінювати | Розділено на `PlayerHealth` / `PlayerHitHandler` / `PlayerRespawn` |
| Різні версії Unity у команді (6000.3.24f1 / 6000.6.3f1) | Unity перезаписує налаштування → конфлікти в `ProjectSettings`/URP | Треба домовитись про одну версію |

## 3. Feedback, повідомлений архітектору

1. Назва файлу має збігатися з класом (`ChargeEnemy.cs` → `ChargerEnemy.cs`).
2. `IEnemyBehaviour` потребує `Initialize` і `IsBusy`, інакше ворог залежить від конкретної поведінки.
3. Animation Events: домовитись, що кожну подію обробляє рівно один компонент.
4. `PlayerAnimationRelay.OnInteractionEvent` більше не використовується — можна прибрати.
5. Одна версія Unity для всієї команди.

### Ітерація 1 — план роботи по блоках

**Prompt:**
> Я в команді з двох людей роблю Unity 2D-платформер, моя роль — AI-assisted Framework Developer.
> Ось список правок від викладача: нова Enemy behaviour через extension API, interaction-анімація з
> Animation Event, Hurt/Death для ворога, спрощення PlayerHealth, документ про мій досвід з API.
> Розбий це на блоки в такому порядку, щоб мені було зручно виконувати і нічого не зламати.
> Для кожного блоку напиши, які файли зачіпаються і як перевірити, що він готовий.

**Відповідь AI (коротко):**
1. Спершу підтягнути актуальні зміни партнерки й працювати в окремій гілці.
2. Блок «ворог»: інтерфейс `IEnemyBehaviour` + `ChargeBehaviour` → перевірка логами Enter/Execute/Exit/Restart.
3. Блок «player»: розділити `PlayerHealth` раніше за анімації, бо Hurt/Death гравця від нього залежать.
4. Блок «анімації»: interaction-подія і Hurt/Death ворога, перевірка тестовими клавішами.
5. В кінці — документ і PR; не редагувати один Animator Controller одночасно з партнеркою.

**Що я взяла / змінила:** порядок блоків залишила, але спершу злила гілку Каті `player-extra-fixes`,

**Перевірка:** після кожного блоку запускала рівень і дивилась логи в Console.

### Ітерація 2 — анімація, яка «просто зникає», і непомітна Hurt-анімація

**Prompt:**
> У мого ворога (міна) є анімація Death, яка просто зменшує scale до 0, і після неї ворог зникає.
> Викладач каже, що цього недостатньо для Hurt/Death. Як правильно зробити Death, щоб це була
> повноцінна реакція, але без combat-системи? І ще: я зробила додаткову Hurt-анімацію, але в грі
> її майже не видно, ніби вона проскакує. Чому так і як це виправити?

**Відповідь AI (коротко):**
- Death має бути станом, а не лише візуалом: на час смерті вимкнути логіку й колайдер ворога, після
  кліпу через Animation Event сховати спрайт і, для тестування, відродити ворога через кілька секунд.
- Перед `Animator.Rebind()` треба повернути scale, інакше Animator запам'ятає scale 0 як стандартний.
- Hurt «проскакує» через таймінги: кліп `Anim_Mine_Hurt` триває 0.167 с, а перехід у нього — 0.25 с,
  тобто кліп закінчується ще під час blend. До того ж перехід Hurt → Idle мав Exit Time = 0
  і стан одразу виходив. Рішення: скоротити перехід, поставити Exit Time = 1, вимкнути Loop Time.

**Що я взяла / змінила:** зробила окремий компонент `EnemyReactions` (J — Hurt, L — Death),
у `BaseEnemy` додала `SetLogicActive`, щоб мертва міна не «вбивала» гравця. Переходи: вхід у Hurt 0.05 с,
Hurt → Idle по Exit Time = 1, вхід у Death без blend. Додала тестові клавіші лише в радіусі гравця,
бо інакше одне натискання вбивало всі міни на рівні.

**Перевірка:** у Play Mode Hurt тепер видно повністю, а Death → зникнення → відродження проходять
по логах `[EnemyReaction]`, і після відродження міна знову реагує на гравця.

### Ітерація 3 — які вороги логічні для нашої гри

**Prompt:**
> Наша гра — 2D-платформер з інерційним рухом у стилі N++: розгін, wall slide, wall jump, dash.
> Вже є PatrolBot, JumpingEnemy, HomingDrone і ProximityMine. Які ще вороги логічно додати, щоб вони
> перевіряли саме ці навички гравця, а не просто стояли на шляху? І яку поведінку краще зробити
> через extension API: Charge, Retreat чи Jump?

**Відповідь AI (коротко):**
- Вороги мають «питати» про рух гравця: патруль — таймінг стрибка, міна — швидку реакцію,
  дрон — постійний рух, стрибун — контроль у повітрі.
- Charge (ривок після попередження) логічно доповнює набір: гравець бачить windup і має встигнути
  ухилитись dash-ем або wall jump-ом. Retreat менш корисний у платформері без атаки гравця,
  а Jump уже частково є в JumpingEnemy.
- Важливо дати чітке попередження перед атакою (колір / миготіння), інакше смерть здається нечесною.

**Що я взяла / змінила:** обрала Charge і зробила `ChargerEnemy` + `ChargeBehaviour`. Додала
миготіння червоним під час windup і повернення на стартову точку з таймаутом (щоб ворог не застряг
у стіні). Поведінка підключається через `GetComponent<IEnemyBehaviour>()`, тож її можна замінити.

**Перевірка:** у `VerticalSlice_Level` і `level2` підходжу до ворога: в Console по черзі
`ENTER → EXECUTE → EXIT → RESTART`, після cooldown він атакує знову.
